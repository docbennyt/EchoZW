## Pause durability patch

PR122 extends PR113. Request-driven recovery uses the existing recovery RPC with
an explicit array of authorized published timetable IDs. The additive overload
rejects null scope and treats an empty array as no work. It applies scope before
the existing 100-job request limit (500 maximum in SQL). The original one-argument
scheduled recovery remains unchanged. There is no new delivery engine.

Publication, corrections, exceptions and pause changes already commit durable
revision intent through database triggers. Jobs coalesce to that revision; replay
does not increase requested generation. Lease ownership, success watermarks,
retry dates and reconnect credential fencing remain unchanged. A larger scope
can leave revisions for the bounded scheduled sweep to recover later.

Pause creation can commit despite failed impact reads. Such unknown scope now
returns deferred recovery, rather than pretending it affected no timetables.
Resumption can likewise commit before scope lookup fails; its response now
preserves the saved outcome. RPC failure after commit returns `pending:true` and
`recoveryDeferred:true`, with zero remote attempts. No response claims a Google
write. Scheduled delivery still requires an enabled authorized delivery policy;
with global delivery disabled, HIT work intentionally remains pending.

Migration `20261028183415_scoped_google_calendar_recovery.sql` was applied to
the live project after independent review and exact-head CI passed at de9123b.
Supabase recorded version `20261028183415`. It creates only a service-role RPC
overload; no backfill, table, credential update or subscriber mutation. Live
verification returned zero jobs for an empty scope, denied anon/authenticated
execution and allowed service_role. The changed Worker is not deployed.
